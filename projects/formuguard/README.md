# FormuGuard-Agent · 带证据核查的专利问答工作流

面向配方专利中的查询与比较。在 QC-RAG 检索之上加入问题拆解、证据引用、声明核查和一次受控修订，把回答中的关键主张定位到检索记录和原文片段。

~~~mermaid
flowchart TD
    Q["用户问题与条件"] --> P["拆解待核查要求"]
    P --> R["调用 QC-RAG 检索"]
    R --> C["构建结构化证据记录"]
    C --> D["草拟声明并绑定证据 ID"]
    D --> V["核查出处、数值和适用条件"]
    V -->|通过或条件缺失| A["回答与证据边界"]
    V -->|可修正且有额度| J["修订一次并重新核查"]
    J --> A
~~~

我重点关注三个问题。如何把用户条件变成明确的检索要求，如何把回答中的主张绑定到可检查的证据，以及如何在证据不充分时保留待确认事项。

## 示例

以下为说明流程用的合成场景。用户希望修改某种薄膜配方，同时改善阻隔性并维持光学性能。检索找到两种配方方案，各自只报告了其中一个指标。

| 工作流环节 | 处理方式 |
| --- | --- |
| 拆解 | 把阻隔性和光学性能拆成两个需要独立核查的要求。 |
| 检索与绑定 | 记录来源、样本身份、数值与单位，以及可定位的证据位置。 |
| 声明核查 | 分别检查两个指标的证据。同一方案缺少任一指标时，把联合要求保留为待确认。 |
| 受控修订 | 草稿若遗漏可用的已绑定证据，允许修订一次，再核查修订内容。 |

目前用本地工程验证检查证据绑定、条件缺失和修订分支。这里展示工作流设计与开发验证，不把探索性运行视为已完成的独立效果评测。
